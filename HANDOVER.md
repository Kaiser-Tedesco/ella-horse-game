## Vet Maths Game — how it works
- A session = **5 questions**. **`longmult` AND `div` are BOTH pinned into every game** at random slots (`shuffle(['longmult','div', ...themes])` in `buildMathPool`; longmult = schriftliche Multiplikation 3×2-stellig; div guaranteed every game since 2026-08). The other 3 walk a **14-theme cycle** (`TOPIC_CYCLE`: add, wt, money, sub, len, tens, compare, round, zeit, halb, vol, estimate, **stellenwert, platzhalter** — `div` was REMOVED from the cycle since it's now pinned; **stellenwert + platzhalter added 2026-09 as Klasse-5 KA1-prep, rotating not pinned**) via a persistent pointer (`ellaTopicCycle`, +3 per session, full coverage every ~5 sessions); all 5 shuffled for display. (`mChooseSlot=0` = the first slot is hers to choose the patient for, whatever type it is.) Theme→concept matching in `themeMatches()` (convert families read from the make() source via `conceptFam()`). Different horses per question where possible (curriculum beats horse variety on fallback).
- **Sachaufgaben mode:** every question starts as story-only (no operation shown, label says "Sachaufgabe"). The **🖐 Hilfe button** (`revealHelp(auto)`, `#mHelpBtn`) reveals `q.label` + `q.problemHTML`, but **only after she has attempted the problem at least once** (`mTried`, set true when a real answer is submitted; a Hilfe tap before any attempt nudges "🤔 Probier zuerst selbst!"). The first wrong answer auto-reveals via `revealHelp(true)`, which bypasses the gate. Help costs nothing; only wrong answers break the perfect bonus. Multi-phase kinds (div step 2, compare pick) set `mHelpShown=true` so Hilfe can't overwrite their step labels.
- **Choose-your-patient:** the **first** of the 4 is hers to choose — "🐴 Welches Pferd braucht dich?" offers 2-3 candidate horses (same maths type, distinct from the other 3). The other 3 are system-picked.
- **All German.** Each question = a vet concept (with a sound-out aid for the technical term, e.g. *Hufabszess (Huf-aps-tsess)*) + a matching maths task.
- **14 skill types:** `longmult` (3×2 digit), `money` (€ × single digit), `compare` (two shops, unit price then dearer), `convert` (fams len/wt/dist/time/**vol**), `div` (estimate first, then exact **with remainder**), plus year-update types `add` (4-digit, carry forced), `sub` (borrow forced), `round` (round to Zehner/Hunderter/Tausender/Zehntausender; the number is sized to the place — ~0.6–9.6× — so it always rounds to a clean 1–10× that place, never 0 and never a place bigger than the number), `tens` (×÷10/100/1000, mode fixed per concept), `halb` (1×3-digit, Hilfe shows the Zerlegung), `estimate` (canonical round-to-hundreds product), `timecalc` (h min + min → minutes), plus the **2026-09 Klasse-5 KA1-prep types** `stellenwert` (Stellenwert / digit value in a 4–6-digit number; asked digit is unique + never 0; Hilfe names the place) and `platzhalter` (fehlende Zahl in a +/− equation, all 4 forms; Hilfe hints the Umkehr-Aufgabe). Builders `Qadd/Qsub/Qround/Qtens/Qhalb/Qestimate/Qtimecalc/Qstellenwert/Qplatzhalter` sit right above `vetConcepts`; story-arg conventions documented in the comment there.
- **`parseNum(v, dec)` is mode-aware** (do NOT revert it to stripping all dots — that broke dot-decimals like `0.054`): if a comma is present → comma is the decimal, dots are Tausenderpunkte; else for a **whole-number** answer (`dec` falsy) any dot is a Tausenderpunkt (`"50.000"`→50000); for a **decimal** answer (`dec` true) a lone dot **or** comma is the decimal point (`"0.054"` and `"0,054"`→0.054). `checkExactNum` gets `dec`; the **convert** case passes `!Number.isInteger(q.answer)` so whole ml/g/m answers accept Tausenderpunkte while kg/l/km decimals parse as decimals. Compared with `near()` for decimals, `===` for whole numbers.

- Items come in **sets** (`COLLECTIBLE_SETS`, currently **3 sets of 9** hand-drawn inline-SVG items each = **27 total**: Set 1 feed/tack basics, Set 2 grooming/care, Set 3 "Turnier & Stall"; extensible, append more sets anytime). Lookup: `COLLECTIBLE_BY_ID`.
- **Drop / refilling supply (reworked 2026-07-07):** ~1-in-4 per heal via `maybeDropCollectible`. The **album** (`ellaCollectProgress` + `ellaCollectSet`) is the "collect one of each" layer, filled set-by-set; on set completion the pointer advances to the next set. **Every drop also pushes a giftable copy into her tray** (`ellaGifts`), so she has trinkets to give from the very first find. **Once all sets are discovered, drops don't stop:** a random item from the full 27-pool drops into the tray, so the giveaway supply keeps refilling (only runs dry if she stops playing). The function returns `{id, name, svg, isNew}`; `isNew` selects the cure-card label ("Neu für deine Sammlung" vs "Zum Verschenken bekommen"). Note the album marks an item collected permanently, independent of whether its giftable copy has been given away. (Old model, pre-2026-07-07: giftables appeared only when a whole set completed, then the whole feature went dead once both sets were collected and all 18 given away.)
- **Gifting (consumptive):** she drags a gift from the album onto a **horse card** (or tap-the-gift-then-tap-the-horse). It's **permanent** on the horse and **removed from her tray** (the tray refills from later drops), shown under **"Geschenke von Ella"** in that horse's info modal. Key: `ellaHorseGifts` (`{horseIdx:[ids]}`). Possible future tidy-up: the tray grows one-per-drop and only shrinks on gifting, so a heavy-play/no-gift streak makes it long (flex-wraps fine); could stack duplicate tokens with a count if desired.

## Flash cards (Mal-Quiz)
- 12 cards/round. Draws ONLY from a **hard-facts pool** `FLASH_HARD` (3/4/6/7/8/9 combinations — no ×1/×2/×5/×10, which she knows cold) and **always includes 4×7 and 4×8**. Facts flip half the time, so she sees 7×4 as well as 4×7.
- **`FLASH_TENS = 3`** of the 12 are a hard fact with one factor ×10 — place-value practice like **3 × 70 = 210** (the ×10 lands on either side at random).
- On a correct answer the input **clears, disables and blurs** before the next card paints, so keystrokes typed during the 650 ms "✅ Richtig!" pause can't land in the old card. Finishing → **+5 vet points, +1 feed play**. No gate.

## Stats — Grown-ups progress charts (2026-08)
- **What's logged:** `recordGameLog()` (called in `showMathEnd`) appends one record per finished Vet-Maths game to **`ellaGameLog`**: `{id, ts, total (sum of per-Q seconds), wrong (# first-try-wrong of 5), bonus, perfect, q:[{k:kind, s:sec, w, b}]}`. Per-Q timing/first-try is captured live in `mSessionQ` (pushed in `mathCorrect`; `sec` = wall-clock from question shown to correct). Kept to the **last 100** games.
- **Synced:** `ellaGameLog` is a normal `ella*` progress key so it mirrors to the cloud, but `mergeKeys` handles it with a dedicated **`unionLog`** (append/union **by `id`**, keep last 100) instead of newest-wins — so iPad + laptop histories **combine** rather than overwrite.
- **UI:** a small **"📊 Ellas Fortschritt"** `admin-link` on the MAIN PAGE, directly under 🔒 Grown-ups (`onclick="showStats()"`) — opens `#statsOverlay` **without the 0101 password** (it's just her times). The overlay is a wide scrollable card `.cure-card.stats-card` (`width:min(94vw,560px)`, `overflow-y:auto`) — **note the 2-class selector: it must out-specify the base `.cure-card`'s `overflow:hidden`/`max-width:470px`, which otherwise clip + block scroll.** Charts are hand-drawn **inline SVG BAR graphs** (`barChart` per-game, `miniBar` per-type, `trendBadge` — no library, **NO averages, actual per-game-play values**): total-time **bars** (one bar = one game), a **per-type bar grid** (each bar = that type's time in one game) with a ⬇ schneller / → stabil / ⬆ langsamer badge, and a first-try-wrongs bar chart. `STAT_TYPE_LABEL` maps kind→German label.
- **Delete (2026-08):** the overlay lists every game (`🗂️ Einzelne Spiele`, oldest first, with date/time/total) each with a per-row **🗑 → `deleteGameRecord(id)`** (keeps the rest — e.g. drop a single test run); plus a footer **🗑 Verlauf löschen → `clearGameLog()`** for the whole log. Both route through `writeGameLog(json)` which writes `ellaGameLog` locally (`setRaw`, no re-mirror) AND **directly in the cloud** (`dbRef.child('keys/ellaGameLog').set(json)`) — the direct set is required so the `unionLog` append-merge can't resync a deleted record. **Do deletes while ONLINE** (offline, the cloud still has it → it comes back next sync; it can also resync from another device that still holds it locally).

## localStorage keys (per device + per browser — NOT in the files)
`ellaVetPoints`, `ellaFeedTokens`, `ellaRankAchieved`, `ellaSeenConcepts`, `ellaNudgeOn` (also the timer on/off), `ellaCollectSet`, `ellaCollectProgress`, `ellaGifts`, `ellaHorseGifts`, `ellaTopicCycle` (theme-cycle pointer, now 0–13 for the 14-theme cycle), **`ellaGameLog`** (game-history array for the stats view — synced via `unionLog` append-merge, last 100). Plus three NON-progress keys that are **not** mirrored to the cloud (in the sync `SKIP` set): `ellaMagicWord` (active player = cloud key), `ellaSyncTs` (last-change timestamp), `ellaPlayers` (device-local player list for the picker). Reset/set via Grown-ups panel (0101) or console.
- **Cross-device save (LIVE) — reworked this session into a progress-only-up MERGE.** A self-contained IIFE at the end of the main `<script>` monkey-patches `localStorage.setItem` to mirror every `ella*` progress key (except the SKIP keys) to a **Firebase Realtime Database** node `saves/<key>`. `FIREBASE_CONFIG` is filled in (project `ella-horse-game`, RTDB `europe-west1`); SDK loaded via two compat `<script>` tags before `</head>`. Key points:
  - **Identity = the active player's name**, lowercased. `fbInit`/`switchToPlayer` build the ref as `saves/` + `getMagicWord().toLowerCase().replace(...)`, so **Ella / ella / ELLA all map to one `saves/ella`** (fixed the "two entries" bug). Load-time also normalises `ellaMagicWord` to its slug.
  - **`syncMerge` (used on open AND on every change, debounced 600 ms)** does an atomic `dbRef.transaction` that merges local + cloud via **`mergeKeys`**: `max` of `ellaVetPoints/ellaRankAchieved/ellaCollectSet`, **union** of `ellaSeenConcepts` + `ellaHorseGifts`, **`unionLog`** append/union-by-id for `ellaGameLog` (last 100), newer-wins for consumables/prefs (`ellaGifts/ellaCollectProgress/ellaFeedTokens/ellaTopicCycle/ellaNudgeOn`). **Progress can only go UP** — a stale/empty device can't drag her rank or horses backward. Replaces the old timestamp last-writer-wins.
  - **`reclaimOldCaseNode`** (once per device, flag `ellaReclaimedCase`): reads the capitalise-first variant (`saves/Ella`) and merges it into `saves/ella` — recovers saves stranded before the case-fix.
  - **Explicit overrides in the panel:** `forceSaveToCloud` (raw `set` — the ONLY way to lower/reset; **2026-08:** confirms ✅ only in `.then` after the write commits, so no false "saved"), `forceLoadFromCloud` (raw overwrite of this PC). Plus the offline **manual base64 backup** (`syncMakeCode`/`syncRestore`). **Flush-on-hide** (`visibilitychange`/`pagehide` → `flushPush`) pushes any pending debounced change before the tab is frozen/closed (esp. iOS).
  - DB rules are **flexible but not wide open**: a specific `saves/<key>` can be read/written if you know the key, but the `saves` root can't be listed (GET `saves/<key>` → 200, root `saves` → 401). Assistant tool-writes to the DB are blocked by a safety guard — do cloud writes via the app/panel, not curl/PowerShell.

A raw side-on full-body shot has the horse's **face at the edge → it gets cropped out of the card**. So when adding/replacing a photo: (1) **view the source image first** to see where the face is; (2) **crop to ~1.3:1 (13:10)** framing the whole horse with its **face clearly inside the frame and not jammed against an edge** (leave a little room in front of the muzzle); (3) resize to ~1000px long edge; (4) **view the OUTPUT before installing** and re-crop if the face is cut or a person/other horse is in frame. Reject shots where a handler is tangled with the head (can't crop out cleanly — e.g. a bold skewbald was rejected for Patches for exactly this; used a clean cremello tobiano instead). Crop+resize+quality all in one `System.Drawing` pass (`DrawImage` with a source Rectangle = crop).
